# Tune 0.5.1 beta release checklist

Ship the new guides and both bug fixes as Hex version `0.5.1` and Git tag
`v0.5.1`. Use GitHub Actions to create the tag, publish the package and
docs, verify the published version, and create the GitHub Release. The
[0.5.0 closeout](2026-11-18-tune-hex-release-checklist.md) records the
earlier tag mismatch and missing GitHub Release.

## Prepare the release PR

- [x] Set the version to `0.5.1` in `mix.exs` and add a `## 0.5.1`
  changelog entry. Mention the guides, both fixes, and beta status. Update
  README links to examples at `v0.5.1`. Check that ExDoc source links use
  that tag and the install requirement admits `0.5.1`.
- [ ] Include all 26 guides in sidebar order, including the 19 Livebooks.
  Check the short sidebar titles, guide links and anchors, and the tarball
  manifest. Include the API introductions and examples for tuning,
  genetic search, retrieval, and agent evals.
- [x] Verify the `:anything` fix. Even when the caller passes
  `use_merge: true`, the report and exported artifact must record
  `use_merge: false`. Run the artifact reload check.
- [x] Verify the runtime usage fix. `Tune.Runtime.run/3` must fill
  `prediction.usage` from the recorded provider responses. Run the success
  and parse failure cases. Both must include the reported tokens from
  each recorded response.
- [x] Run `mix test`, `mix quality`, `mix docs`, and
  `bash .github/scripts/check-docs.sh`. Run the guides in Livebook against
  the release candidate and check the expected cell outputs. Use scripted
  responses. Track the opt-in live LLM eval separately in the
  [roadmap](roadmap.md).

The local candidate passed 328 tests and the quality and docs checks.
All 25 runnable guides passed in Livebook using scripted responses for
the model examples.

## Verify GitHub CI and release preflight

On 2026-11-19, `hex-publish` allowed `v*` tags and had an
`HEX_API_KEY` secret. GitHub reported no required environment reviewers
and no active rules on `main`.

- [ ] Confirm the publish key scope and repository settings with the
  release owner. Check that CI and the dry run need no publish credential.
  Confirm who can authorize the publish dispatch and who can approve a
  staged release on Hex.
  [Release procedure](../releasing.md)
- [ ] Exercise the failure paths with fixtures or in an isolated test
  repository. Check that the workflow stops for a tag/version mismatch, a
  missing changelog entry, a commit outside `main`, or missing or failed
  CI for the release commit. Check that `prepare` rejects a tag that
  already points to a different commit. Check that changed package files
  or metadata stop publish and that a checksum mismatch stops GitHub
  Release creation.
- [x] Verify that a dry run on `main` requires an explicit version tag
  and that publish and finalize require a tag ref.
- [ ] Merge the release PR. Verify that the CI run from the push to
  `main` passes on the exact commit to tag. Check the two Elixir/OTP
  pairs, quality, docs, dependency audit, and package installs. Save the
  run URL, commit SHA, and package artifact.
- [ ] Run `release.yml` on `main` with `operation=dry-run` and
  `tag_name=v0.5.1` to verify the candidate package. Check that the
  tag creation, publish, and GitHub Release jobs are skipped.
- [ ] Run `release.yml` on `main` with `operation=prepare` and
  `tag_name=v0.5.1` after approval. Verify that Actions creates the
  annotated tag after preflight passes and that the remote tag resolves
  to the exact CI commit.
- [ ] Run `release.yml` with `operation=dry-run` on the new tag. Check
  that only verification and preflight ran. Save the manifest and
  SHA-256 from the `tune-hex` artifact. Compare the manifest with the CI
  artifact and check that the tarball includes the guides and excludes
  internal development docs. Preflight must pass both unpacked package
  installs and the Hex dry run.

## Publish from GitHub and verify from Hex

- [ ] With release approval, run `release.yml` with `operation=publish`
  on the same tag. If a GitHub environment reviewer is required, compare
  the preflight archive SHA-256 with the tag dry run before approving the
  job. Verify the checksums match and the publish job compares the
  rebuilt file list, file contents, and metadata before sending the
  package to Hex. Record the workflow URL and any environment approval.
- [ ] If Hex stages the publication, check the package, version, and
  checksum before approving with 2FA. Record whether Hex staged the
  release and whether the waiting job finished.
  [Hex staged publishing](https://hexdocs.pm/hex/Mix.Tasks.Hex.Publish.html#module-staged-publishing)
- [ ] Confirm that Actions compares the Hex API checksum and downloaded
  archive SHA-256 with the verified build. The GitHub Release job must
  check HexDocs and pass fresh installs from Hex with and without the
  workbench before it creates the Release. Check the Release tag,
  changelog notes, Hex links, and checksum.
- [ ] Open the 0.5.1 HexDocs sidebar and the tagged example links. In clean
  Livebook sessions, run the published notebooks with `tune` resolved to
  exactly `0.5.1` and check the outputs.
- [ ] Test `operation=finalize` on the published tag. It must verify
  the checksum and complete with the same GitHub Release record and the
  publish job skipped. If the initial publish run fails after Hex goes
  live, verify the checksum and use `finalize` to create the missing
  GitHub Release. If Hex never publishes, diagnose the failure before
  retrying `publish`. [Release procedure](../releasing.md)
- [ ] Record the tagged SHA, CI and Release workflow URLs, artifact
  checksum, Hex and HexDocs URLs, GitHub Release URL, and fresh-install
  results. Close this checklist when all three public records consistently
  identify the same version and source.
